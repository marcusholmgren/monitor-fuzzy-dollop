# ADR 002: Command Pattern Application Architecture (ArjanCodes Style)

## Status

Accepted

## Context

FastAPI endpoints should remain thin HTTP adapters. Domain logic, database validation (e.g., verifying `house_id` and `sensor_id` registration), error mapping, and transaction boundaries must be separated from routing and transport mechanics.

We want an explicit **Command Pattern** (as popularized by ArjanCodes), separating the intent (Commands/Queries), the execution logic (Handlers), and the input parameters (Dataclasses/Pydantic schemas).

## Decision

We will structure the application into distinct layers:

1. **Transport Layer (`api/`):** FastAPI route handlers receive requests, parse Pydantic schemas, and pass them to Command/Query dispatchers.
2. **Commands & Queries (`commands/`, `queries/`):** Clean domain objects encapsulating the parameters required to execute an action.
3. **Handlers (`handlers/`):** Callable classes or protocols responsible for coordinating business validation and database transactions.
4. **Database Context:** Handlers receive an acquired `AsyncConnection` from the `psycopg_pool.AsyncConnectionPool` injected via FastAPI dependencies.

### Architecture Layout

```text
src/
├── api/
│   ├── dependencies.py      # Pool & connection injectors
│   └── v1/
│       ├── ingestion.py      # POST /readings (batch)
│       └── readings.py       # GET /readings (cursor keyset)
├── core/
│   └── cursor.py             # Encode/decode base64 keyset tokens
├── domain/
│   ├── commands.py           # IngestReadingsBatchCommand
│   └── queries.py            # GetReadingsKeysetQuery
├── handlers/
│   ├── ingest_readings.py    # Validates FKs & executes batch insert
│   └── get_readings.py       # Evaluates cursor & runs keyset query
└── db/
    └── pool.py               # psycopg async pool lifecycle

```

### Pattern Mechanics

#### 1. Command Definition

```python
from dataclasses import dataclass
from datetime import datetime
from uuid import UUID


@dataclass(frozen=True, slots=True)
class ReadingItem:
  sensor_id: UUID
  house_id: UUID
  recorded_at: datetime
  metric_value: float


@dataclass(frozen=True, slots=True)
class IngestReadingsBatchCommand:
  items: list[ReadingItem]

```

#### 2. Handler Protocol & Execution

The handler performs the strict pre-registration foreign-key checks:

1. Extract distinct `(house_id, sensor_id)` pairs from the batch.
2. Query the registered `sensors` table to ensure every pair exists.
3. If any are missing, raise a domain error `UnregisteredEntitiesException` (translated to HTTP 422/400 by an exception handler).
4. If valid, execute batch insert with `ON CONFLICT (sensor_id, recorded_at) DO NOTHING`.

```python
class IngestReadingsHandler:

  def __init__(self, conn: psycopg.AsyncConnection):
    self.conn = conn

  async def execute(self, command: IngestReadingsBatchCommand) -> int:
    # 1. Validate foreign keys in-db
    # 2. Execute batch insert with ON CONFLICT DO NOTHING
    ...

```

#### 3. FastAPI Route Integration

Routes do not contain SQL or business validation:

```python
@router.post("/readings", status_code=status.HTTP_201_CREATED)
async def ingest_readings(
    payload: IngestReadingsRequest,  # Pydantic schema
    conn: Annotated[
        psycopg.AsyncConnection, Depends(get_db_connection)
    ],  # Dependency
):
  command = payload.to_command()
  handler = IngestReadingsHandler(conn)
  inserted_count = await handler.execute(command)
  return {"inserted": inserted_count}

```

## Consequences

### Positive

* **Testability:** Handlers can be tested with mock connections or against isolated test transactions without spinning up the FastAPI HTTP stack.
* **Single Responsibility:** Routes handle HTTP status codes, headers, and schemas; handlers enforce FK constraints and ingestion rules.
* **Zero Framework Lock-in:** The command layer has no dependencies on FastAPI, allowing command reuse from a CLI runner or background worker if needed later.

### Negative

* Slightly more boilerplate per endpoint (schemas $\rightarrow$ commands $\rightarrow$ handlers).
* Handlers require explicit transaction lifecycle handling (`async with conn.transaction():`) instead of relying on implicit ORM sessions.
